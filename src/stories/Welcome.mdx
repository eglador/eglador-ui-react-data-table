Schema-driven, accessible data table for React — reads columns, filters, sort, includes, pagination, and form metadata from a single endpoint and wires the table automatically. Tailwind v4, zero runtime dependencies, TypeScript-first.

---

## What is schema-driven?

The backend exposes a `/api/v1/schema/{resource}` endpoint with every field's metadata in one place:

```json
{
  "data": {
    "type": "articles",
    "labels": { "singular": "Article", "plural": "Articles" },
    "fields": {
      "title": {
        "type": "string",
        "label": "Title",
        "in": ["list", "show", "create", "update"],
        "sortable": true,
        "searchable": true,
        "filter": { "operator": "partial" },
        "form": { "input": "text", "required": true, "max": 255 }
      }
    },
    "relations": {
      "category": { "type": "belongs_to", "target": "categories", "label": "Category", "default_loaded": true, "in": ["list", "show"] }
    },
    "virtual_filters": [
      { "field": "search", "operator": "fulltext", "label": "Search", "min_length": 2 }
    ],
    "endpoints": {
      "list": { "method": "GET", "path": "", "default_sort": "-published_at", "pagination": { "default_size": 15, "max_size": 100 } }
    }
  }
}
```

The frontend side is just:

```tsx
<DataTable endpoint="/api/v1/articles" />
```

Wired automatically:

- Column headers, filter chips, search placeholder — from schema labels
- Sortable columns — when `field.sortable === true`
- Default sort — from `endpoints.list.default_sort`
- Filter UI type — picked from `field.filter.operator` (date / select / boolean / text)
- Async select options — fetched from `field.source` lookup endpoint
- Relation rendering — auto-extracted from `name` / `title` / `slug`
- Default visible column control — `field.default_visible: false`
- Pagination params — `pagination.number_parameter / size_parameter`
- Title — from `labels.plural`

## Highlights

- **Schema-driven** — backend is the single source of truth; the frontend never hand-configures columns
- **Compound API** — `<DataTable.Root>`, `.Header`, `.Body`, `.Row`, `.Cell`, `.Toolbar`, `.Search`, `.FilterBar`, `.Pagination`, etc. for full markup control
- **Headless hooks** — `useDataTable`, `useAutoColumns`, `useSchema` — build your own render
- **Spatie Query Builder adapter** — `filter[X]=Y`, `sort=-X`, `include=a,b`, `page[size]=N`
- **16 filter operators** — eq, neq, gt, gte, lt, lte, contains, starts_with, ends_with, in, not_in, between, is_null, is_not_null, is_true, is_false
- **Multi-sort** — Shift/Cmd + click
- **Selection** — single / multiple, controlled & uncontrolled
- **URL sync** — Next.js / React Router / manual adapter
- **Density** — compact / comfortable / spacious
- **Variants** — default / bordered / striped / minimal
- **Sticky header & footer** — enabled by container `maxHeight`
- **Custom columns** — render override, accessor, label, width, sticky, align
- **Added columns** — select / drag / actions / expander
- **Auto relation rendering** — `category.name` / `tags[].name` auto-derived
- **i18n** — every label comes from the schema (generic UI strings are separate)
- **Tailwind v4** — zinc-only palette, `rounded-sm`, modern utility-first
- **Zero runtime deps** — `clsx` + `tailwind-merge` pre-bundled
- **TypeScript-first** — generic over row shape, schema-typed end-to-end
